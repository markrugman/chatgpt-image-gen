# Use native Codex app-server for ChatGPT image generation

The user requires ChatGPT subscription/device access and rejected separately billed Image API access. The native Codex app-server integration was verified on 2026-10-15 with actual image generation, editing from two references, conversation restart recovery, historical forks, and interruption; the separate public Sign in with ChatGPT Responses route has different tool restrictions. Keep authentication and inference in the official app-server process, and own document history, compositions, and image copies in the app so Codex session storage is not the only copy of a finished design.

Desktop isolation decision (2026-10-15): Mark confirmed the problem is Image Gen prompts appearing in Codex recent chats; ChatGPT's Images section contains only images created through ChatGPT itself. From 0.8.3, desktop generation must use its bundled runtime exclusively, with child-process `CODEX_HOME` fixed to Image Gen's private `sessions/codex` directory. Require ChatGPT login, use private file-based managed credentials, and remove inherited API keys/access tokens. Never copy normal Codex credentials/history or fall back to an installed executable. Existing page transcripts and image copies remain app-owned; missing old runtime threads use the existing context-recovery path. The browser worker already uses its private `/worker/codex` directory.
